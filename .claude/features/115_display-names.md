# Clean display names + editable aliases

## Description
Entities show the raw Home Assistant friendly name, which is long, repeats the device name, has double spaces and mixes Spanish/English while the UI is English (real examples: "Backup Estado del administrador de copias de seguridad", "ENCERRADO EN EL PATIO  Batería", "RT-AC65P Velocidad de descarga", "samsung s24 hector Battery level"). This feature cleans names automatically and lets the user rename any entity inline; aliases are stored in the backend (backend feature 008, `/api/aliases`) so every client (browser, Electron, phone) shows the same names. No automatic translation: a user alias is the language mechanism.

## Requirements
- **Contract:** refresh the read-only `.claude/endpoints.md` from `../home-control-backend/.claude/endpoints.md` (the copy here is stale) once backend 008 has its rows. Consumes `GET /api/aliases` -> `[{ entityId, alias }]`, `PUT /api/aliases/:entityId` `{ alias }` -> `[{ entityId, alias }]`, `DELETE /api/aliases/:entityId` -> `[]`. Errors `invalid_entity_id`, `invalid_alias`, `too_many_aliases` (400), `aliases_write_failed` (500). Entities from `/api/entities`, `/api/areas`, `/api/stream` have NO alias field: the client merges.
- **Device name (backend 009 `entity-device-names`):** entities from `/api/entities`, `/api/areas`, the action response and `/api/stream` carry `deviceName: string | null` (HA device registry `name_by_user` or `name`; `null` = no device or backend lookup failed). `Entity` in `api/types.ts` gets optional `deviceName?: string | null`; `liveApi` passes it through. Live mode depends on 009 for prefix stripping but works without it: field absent/`null` -> no prefix stripping (the rest of the cleanup still applies). When a stream/action entity arrives without the field (`undefined`, older backend) the store keeps the entity's previous `deviceName`.
- **HomeApi** (`src/api/HomeApi.ts`): add `getAliases(): Promise<Alias[]>`, `setAlias(entityId, alias): Promise<Alias>`, `deleteAlias(entityId): Promise<void>`; `Alias = { entityId: string; alias: string }` in `api/types.ts`. Live impl in `liveApi.ts` (encodeURIComponent on the id, same auth/error mapping as other calls; 404 on GET -> `not_found`). Unit tests in `liveApi.test.ts`.
- **Cleanup** (`src/features/names/displayName.ts`, pure, no React). Decision (replaces the earlier sibling-guessing rule, which failed on "RT-AC65P Velocidad de descarga" -> "descarga" and on "Bedroom lamp"/"Bedroom blinds"): the device prefix is NEVER inferred from other entity names; only the real HA device name from the backend (`entity.deviceName`, backend 009) is stripped.
  - `cleanName(entity, { areaName?, stripArea })`, steps in order:
    - (a) trim + collapse whitespace runs to one space (also applied to `deviceName` before comparing).
    - (b) device strip: if `entity.deviceName` is a non-empty string AND the name starts with it case-insensitively AND the next character is a space AND the remainder (trimmed) is non-empty -> keep only the remainder. Otherwise keep the name as is (no `deviceName`, name equal to the device name, or no word boundary -> nothing stripped). No sibling/prefix guessing at all.
    - (c) ALL CAPS fix: a run of >= 2 consecutive letter-only all-caps tokens containing one of >= 4 letters is lowercased (keeps acronyms such as "TV", "LED", "CO2", "PM2.5", "RT-AC65P", "HVAC filter life"); then uppercase the first letter (sentence case).
    - (d) area strip, only when `stripArea` (visible titles that already show the area next to the name) AND step (b) stripped nothing: if the name starts with the area name case-insensitively at a word boundary and the remainder is non-empty -> strip it, then re-apply the first-letter uppercase. At most one strip per name.
  - Empty input -> entityId. Idempotent on already-clean names. Pure function of the entity + area, so nothing to memoize across entities.
  - Two outputs, both overridden by the alias verbatim when one exists: `displayName` (no area strip) for accessible names, toasts, event feed, gauges, history bars; `shortName` (area strip) for visible card titles that already show the area next to the name.
  - With the default mock fixtures `displayName` must equal the current names (no locator churn in existing specs): default fixtures have `deviceName: null` (e.g. "Bedroom lamp" and "Bedroom blinds" stay unchanged); `shortName` may shorten ("Living room ceiling" in Living room -> "Ceiling").
  - Unit tests (input name + `deviceName` -> `displayName`): "RT-AC65P Velocidad de descarga" + "RT-AC65P" -> "Velocidad de descarga"; "samsung s24 hector Battery level" + "samsung s24 hector" -> "Battery level"; "Backup Estado del administrador de copias de seguridad" + "Backup" -> "Estado del administrador de copias de seguridad"; "ENCERRADO EN EL PATIO  Batería" + "ENCERRADO EN EL PATIO" -> "Batería" (double space collapsed first); "ENCERRADO EN EL PATIO  Batería" + `null` -> "Encerrado en el patio Batería"; case-insensitive match ("rt-ac65p Velocidad de subida" + "RT-AC65P" -> "Velocidad de subida"); no word boundary ("Backupper status" + "Backup" -> unchanged); name equal to the device name ("RT-AC65P" + "RT-AC65P" -> "RT-AC65P"); `deviceName` absent/`null`/"" -> nothing stripped ("Bedroom lamp" stays "Bedroom lamp" even next to "Bedroom blinds"); `shortName` area strip only without a device strip; alias wins; idempotence; default fixtures unchanged.
- **Store:** aliases live next to the entities store (extend `EntitiesProvider` or a small `AliasesProvider` under it): `aliases: Record<entityId, string>`, `aliasesStatus: "loading" | "ready" | "unavailable" | "error"`. Loaded once in parallel with `getAreas` (and again on Retry); failure never blocks the panel (cleaned names shown). `not_found` (backend without 008) -> `unavailable`: rename UI hidden. Hook `useEntityName()` -> `{ displayName(entity), shortName(entity), rawName(entity), renameEntity(entityId, alias) }`.
- **Rename** (`renameEntity`): normalize client-side (trim, collapse, max 80); empty, or equal to the cleaned name -> `deleteAlias` (reset); unchanged -> no request. Optimistic update; on failure roll back to the previous alias and show toast "Could not rename <displayName>" (existing `useToast`). Concurrent renames of the same entity: the latest wins (request counter, like 104).
- **UI** (`EditableName` in `src/components/controls`, reused by both cards; tokens + lucide only, DESIGN.md rules):
  - Visible name + pencil button (lucide `Pencil`, 44x44 target, `aria-label="Rename <displayName>"`), hidden when `aliasesStatus` is `unavailable`.
  - Edit mode: text input (`aria-label="Name for <entityId>"`, `maxLength=80`, autofocus + select all, prefilled with the current display name). Enter saves, Esc cancels and returns focus to the pencil, blur cancels. Hint line in `label-caps`: "ENTER SAVE • ESC CANCEL • EMPTY RESETS". While saving: input disabled + mono "SENDING".
  - Name element `title` = raw HA name (+ entityId) when it differs from what is shown (no extra "alias" badge).
  - Used in `DeviceModule` (title) and `SensorChartCard` (title). Focus ring and contrast per DESIGN.md.
- **Where names render — switch from `entity.name` to the hook** (visible -> `shortName` only where the area is shown alongside, everything else `displayName`):
  - `components/cards/DeviceModule.tsx` (title, `aria-label`, toast text), `components/cards/DeviceControls.tsx` (switch/lock aria-labels, unlock confirm text), `components/cards/SensorChartCard.tsx` (title, region aria-label, chart summary), `components/cards/EventFeed.tsx` + `state/feed.ts` (feed resolves the name at render time, so a rename updates past events), `components/cards/PowerHistoryBars.tsx`, `features/telemetry/telemetry.ts` gauge labels (RingGauge), plus any other `entity.name` render found by grep at build time.
  - Keep raw `entity.name` (do NOT alias) in matching logic: `state/selectors.ts` (sensor/switch pairing, house-power regex), `features/telemetry/history.ts` and `telemetry.ts` regexes (`house|total`, `solar`), sort orders (`createMockApi`, `widgets.ts`): renaming must not reorder cards or break pairing.
- **Mock** (`src/api/mock`): implement the 3 alias methods. Aliases persisted in `localStorage` key `hc.mock.aliases.v1` (try/catch, corrupt -> empty) so reload keeps them in mock mode; same validation as the backend (regex, 1..80, 2000 cap -> `ApiError` with the backend error codes). New scenarios: `alias-error` (setAlias/deleteAlias reject `aliases_write_failed`), `raw-names` (adds the real example entities in `unassigned`, so cleanup is visible in dev): "RT-AC65P Velocidad de descarga" / "RT-AC65P Velocidad de subida" (deviceName "RT-AC65P"), "samsung s24 hector Battery level" / "samsung s24 hector Battery state" (deviceName "samsung s24 hector"), "Backup Estado del administrador de copias de seguridad" / "Backup Próxima copia de seguridad" (deviceName "Backup"), "ENCERRADO EN EL PATIO  Batería" / "ENCERRADO EN EL PATIO  Temperatura" (deviceName "ENCERRADO EN EL PATIO", raw double space kept in the fixture). All default fixtures get `deviceName: null`. Mock action/stream entities carry the same `deviceName` as the fixture. `empty` -> no aliases; `error` -> getAliases rejects too. Document scenarios in README + notes.
- **States:** aliases loading -> cleaned names (no skeleton of their own); aliases error -> cleaned names + rename still offered (a save retries the backend); unavailable -> no pencil; the panel's own loading/empty/error/success states unchanged.

  - Playwright (mock, new `e2e/specs/display-names.spec.ts`; extend `e2e/components/device-card.ts` with `rename(name)`/`startRename()`, and `e2e/pages/telemetry.ts` for chart cards): rename a device card with Enter -> new name shown and survives reload; Esc cancels; empty resets to the cleaned name; rename on a sensor chart card updates its title; `?mock=alias-error` rolls back and shows the toast; `?mock=raw-names` shows "Velocidad de descarga", "Battery level", "Estado del administrador de copias de seguridad" and "Batería" on cards with the raw name in `title`.
